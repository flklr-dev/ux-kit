# Motivation And Complexity

Separate impressions, remembered experience and actual completion. Never manufacture progress, impose a timing law or infer an eighty/twenty ratio. Keep truthful progress and user control. Use task evidence to decide which complexity the system can absorb without obscuring meaningful decisions.

- [Aesthetic–Usability Effect](../principles/aesthetic-usability-effect.md): Separate favorable first impressions from observed task success.
- [Flow](../principles/flow.md): Reduce avoidable interruption during sustained creation work.
- [Goal-Gradient Effect](../principles/goal-gradient-effect.md): Communicate truthful progress toward a meaningful goal.
- [Doherty Threshold](../principles/doherty-threshold.md): Investigate responsiveness and feedback without a universal timing promise.
- [Occam’s Razor](../principles/occams-razor.md): Prefer an explanation or design with fewer unsupported assumptions.
- [Paradox of the Active User](../principles/paradox-of-the-active-user.md): Make first useful action possible without requiring a manual.
- [Pareto Principle](../principles/pareto-principle.md): Use observed task frequency rather than assume an 80/20 split.
- [Parkinson’s Law](../principles/parkinsons-law.md): Investigate unnecessary workflow overhead without imposing arbitrary deadlines.
- [Peak–End Rule](../principles/peak-end-rule.md): Improve important moments and endings without neglecting intervening failures.
- [Tesler’s Law](../principles/teslers-law.md): Decide which task complexity the system should handle and which users need visible.

Preserve successful behavior. Prefer scoped accessibility and platform requirements over a conflicting heuristic; report evidence limits.
