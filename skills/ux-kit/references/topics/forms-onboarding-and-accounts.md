# Forms Onboarding And Accounts

Work through entry, invalid submission, correction, service failure and success. Preserve valid values and show persistent purpose. Input semantics, optionality, correction timing and authentication requirements are separate decisions. Account and progress patterns must follow real service needs, not assumed conversion tactics.

- [Preserve Usable Work During Correction](../principles/preserve-work.md): Keep valid values after a failed form submission.
- [Error Identification and Correction](../principles/errors.md): Identify the affected field and a useful next correction.
- [Persistent Field Labels](../principles/persistent-field-labels.md): Keep a field’s meaning visible while a value is entered.
- [Semantic Input and Autofill](../principles/semantic-input-and-autofill.md): Choose input purpose and autofill behavior that fits the data.
- [Validation Timing](../principles/validation-timing.md): Give corrective feedback when the user can use it.
- [Required and Optional Information](../principles/required-and-optional-information.md): Make required effort and optional inputs clear.
- [Accessible Authentication](../principles/accessible-authentication.md): Support authentication without unnecessary memory or transcription barriers.
- [Check Answers Before Commitment](../principles/check-answers-before-commitment.md): Allow correction of consequential information before sending it.
- [Progressive Profiling](../principles/progressive-profiling.md): Ask for information when it becomes necessary for the service.
- [Multi-Step Progress and Branching](../principles/multi-step-progress-and-branching.md): Communicate meaningful progress through conditional form paths.

Preserve successful behavior. Prefer scoped accessibility and platform requirements over a conflicting heuristic; report evidence limits.
