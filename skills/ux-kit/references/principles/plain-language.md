**Explanation:** Write for the intended audience's task and knowledge, explaining necessary unfamiliar terms.

**Signals:** A service instruction uses internal acronyms and hides who must act.

**Interventions:** Use concrete task language and a clear next step; retain precision needed for the consequence.

**Limits:** Shorter text is not automatically clearer and specialist audiences may need exact terms.

**Example:** A failed upload says which file needs attention and what can be retried, using the real failure reason.

**Validation:** Ask relevant readers to explain the action and carry it out; preserve necessary technical meaning.

**Counterexample:** Replacing a precise technical condition with friendly vague reassurance can mislead experts.

**Conflicts:** Balance plain wording with truthful scope and established domain terminology.

**Evidence boundary:** Official reader-focused guidance inspected; exact comprehension for this audience remains untested.

**Useful when:** Make instructions understandable to the intended audience.
