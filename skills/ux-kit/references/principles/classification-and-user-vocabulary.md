**Explanation:** Investigate category boundaries using how relevant people group content; naming and successful retrieval need separate checks.

**Signals:** A menu reflects internal departments and participants place expected items in several competing categories.

**Interventions:** Use representative content in grouping research, examine disagreements and then test task retrieval in the proposed structure.

**Limits:** A card sort does not establish live findability, and similar keywords may dominate grouping.

**Example:** A help taxonomy tests whether people place Refund status with Orders or Payments before choosing labels and cross-links.

**Validation:** Record grouping rationale and later first-click/tree-task success for real information needs.

**Counterexample:** A unanimous sort of obvious keywords may still fail when users search by a different task concept.

**Conflicts:** Balance familiar terms, overlapping content and multiple valid entry paths.

**Evidence boundary:** First-party method description inspected; classification hypotheses are not validated user mental models by default.

**Useful when:** Test category boundaries against how people organize the content.
