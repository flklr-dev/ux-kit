**Explanation:** A perceivable cue can communicate what is possible or happening; its meaning and reliability depend on context.

**Signals:** A blank area accepts uploads but gives no visible indication of that action.

**Interventions:** Provide a clear action label and state cue with an equivalent operable control.

**Limits:** A cue may mislead if the advertised action is unavailable; hover alone excludes some inputs.

**Example:** An attachment area says Choose files and exposes a native file control alongside optional dropping.

**Validation:** Check whether users locate the action and complete it without hover or drag; test error feedback.

**Counterexample:** A decorative underlined heading looks like a link but does nothing.

**Conflicts:** Truthful capability and accessibility govern which cue is appropriate.

**Evidence boundary:** Norman's signifier account inspected; the file-picker example is original design practice requiring task checks.

**Useful when:** Communicate that an element can be edited, dragged or opened.
