**Explanation:** When people need a value or action, making it recognizable can avoid unnecessary recall.

**Signals:** A person must remember the exact prior invoice code to continue editing.

**Interventions:** Show recent relevant choices, labels and current selections; allow search and correction.

**Limits:** Recognition aids must respect privacy and relevance; showing every historical value can distract.

**Example:** An invoice editor offers recent authorized project names while retaining free search.

**Validation:** Have users resume an interrupted invoice and find the correct project without external notes.

**Counterexample:** A public kiosk must not expose the last person's private recipient list.

**Conflicts:** Balance accessible context with privacy and visual priority.

**Evidence boundary:** NN/g provides heuristic guidance; the invoice application and its benefit need task verification.

**Useful when:** Show available actions and previously selected values.
