**Explanation:** Check which task facts people must retain while switching views. Externalizing a needed fact is different from reducing the number of available choices.

**Signals:** A user must memorize the prior month's total to compare a new month.

**Interventions:** Keep baseline and candidate values together, or retain a readable comparison summary across navigation.

**Limits:** Do not use fixed chunk counts or memory durations as interface quotas.

**Example:** A budget comparison keeps both month names and totals visible while a person adjusts categories.

**Validation:** Ask users to compare the actual values after a realistic interruption; record errors and lost context.

**Counterexample:** An expert's eight useful columns can remain visible without requiring eight items to be memorized.

**Conflicts:** Prefer visible comparison to a staged sequence that creates memory work.

**Evidence boundary:** Popular memory claims are not validated here; the comparison technique is an original task application, not a numeric cognitive limit.

**Useful when:** Keep comparison information visible while users make a decision.
