**Explanation:** Choose navigation around the real tasks and whether they are repeatable, independent or ordered.

**Signals:** An organizational menu forces a user through departments to complete one request.

**Interventions:** Map task starts and returns; use navigation for recurring independent work and fitting task progress for ordered work.

**Limits:** GOV.UK component policy is context-specific; no universal menu size or workflow depth follows.

**Example:** A maintenance tool gives recurring access to Jobs and Assets while keeping a one-off submission sequence coherent.

**Validation:** Observe representative task starts, switching and return without teaching the menu first.

**Counterexample:** A forced linear wizard blocks dispatchers who compare several open jobs repeatedly.

**Conflicts:** Preserve expert task switching and use actual vocabulary rather than a cosmetic category reduction.

**Evidence boundary:** Official service-pattern guidance inspected; the maintenance IA is an original hypothesis requiring retrieval checks.

**Useful when:** Organize navigation around real user tasks.
