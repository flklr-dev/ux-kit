Installation

Use a Codex or Claude Code version that supports local Agent Skills. The command-line route requires Node.js and npm. UX Kit itself is a folder of instructions and references, with no runtime or API key requirement.

Codex

From your project directory:

npx skills@1.7.4 add flklr-dev/ux-kit --skill ux-kit -a codex --copy
npx skills@1.7.4 list -a codex

The project destination is .agents/skills/ux-kit/. In your agent chat:

$ux-kit Audit this checkout. Preserve what works.
Give prioritized fixes and checks. Do not edit files.

You can also select the skill through your client’s skill picker. Start a new session if discovery does not refresh.

Claude Code

npx skills@1.7.4 add flklr-dev/ux-kit --skill ux-kit -a claude-code --copy
npx skills@1.7.4 list -a claude-code

The project destination is .claude/skills/ux-kit/. Invoke it in your agent chat:

/ux-kit Audit this checkout. Preserve what works.
Give prioritized fixes and checks. Do not edit files.

Manual & user installation

Download the complete skill ZIP, extract it, and copy the ux-kit folder to the appropriate directory. Keep SKILL.md, LICENSE.txt, agents/ and all references together.

~ means your home folder; on Windows this is typically C:\Users\YourName. Check for a customized existing copy before replacing it. Keep one intended version so your agent loads the right instructions.

For Codex’s built-in installer, ask: “Use skill-installer to install UX Kit from flklr-dev/ux-kit, path skills/ux-kit, for my user account. Preserve any existing customized copy.” Use the destination that installer reports.

Four workflows

Describe the outcome in ordinary language. You do not need separate slash commands for each mode.

Design

Explore a proposed journey, important states, tradeoffs and validation before changing the product.

Use UX Kit to design our invite flow. Include roles,
expired invites, duplicates and recovery.
Preserve the existing account model. Propose first.

Audit

Diagnose a few important problems using the available evidence. An audit does not authorize product edits.

Use UX Kit to audit this screen and its code.
Prioritize usability problems, preserve working patterns,
and give concrete recommendations and checks.
Do not edit files.

Implement

Make the authorized changes using the project’s existing stack, components and design system.

Use UX Kit to implement the agreed form-error fixes.
Keep entered values and the existing visual style.
Verify correction, keyboard use and retry.

Validate

Compare a supplied fix with the original problem and its acceptance checks.

Use UX Kit to validate this fix against the original
checkout issue. Report observed results and remaining
gaps. Do not make additional changes.

Bring the real task

A useful request includes who is using the feature, what they are trying to do, the platform, what must remain, and the evidence you can provide.

  • A screenshot helps inspect wording, hierarchy and visible controls.
  • Source code can reveal behavior, constraints and missing states.
  • A running interface allows interaction, keyboard, layout and recovery checks.
  • User observations help distinguish a plausible concern from a recurring difficulty.

Missing evidence should stay visible as uncertainty. A still image cannot establish loading, keyboard, network or recovery behavior.

Grounded, not absolute

The library mixes different kinds of guidance. Check the source, conditions and limitations before applying any entry.

Research
Fitts-related target acquisition, Hick’s choice-response work, Miller’s memory work and Gestalt research inform questions to investigate. They do not establish universal menu sizes or guaranteed speed gains.
Heuristics
Nielsen’s usability heuristics, Norman’s signifiers and named Laws of UX concepts provide useful ways to inspect an experience. They remain conditional guidance.
Standards & platforms
WCAG requirements and native platform guidance carry their own scope. Informative explanations are distinguished from normative requirements.
Patterns & methods
Recovery, action guards, content, consent, research and evaluation entries connect principles to product decisions and checks.

Read the research bibliography or inspect the source registry. Original third-party works retain their authors’ rights.

Check the result

A recommendation should explain the location, user consequence, evidence, intervention and check. Keep impact separate from confidence.

  • Does the change address the original problem?
  • Are useful copy, behavior, imagery and choices preserved?
  • Do success, error, empty, pending and recovery states make sense?
  • Can people use the relevant controls with a keyboard and at narrow widths?
  • Are costs, permissions and commitments truthful?
  • What still needs device testing or observation with real users?

Automated checks assist review; they do not establish complete accessibility conformance. UX Kit’s verification record distinguishes checked installation and source integrity from unverified native behavior and broader effectiveness.

Find the right copy

The skill is missing

Check that SKILL.md is inside the expected agent directory and start a new session. For Claude Code, launch it in the project containing your installation.

The agent uses old instructions

Look for a personal and project copy with the same name. Preserve local customizations, then keep one intended version. Back up changes before updating.

References cannot be found

Copy the complete skill folder, not just SKILL.md. All references must retain their relative paths.

npm or npx is unavailable

Use the ZIP/manual route above, or install Node.js/npm through your preferred official method. The skill itself does not require npm after installation.
